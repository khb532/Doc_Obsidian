# 탄도 시스템 분석 및 개선 방향

> 작성일: 2026년 04월 15일  
> 유형: 심층 메모

---

## 배경

MYP 프로젝트 CoD 브랜치에서 라이플탄 탄도 시뮬레이션 구현 완료 후, 로켓탄 컴포넌트 작업 진입 전에 현재 베이스 컴포넌트(`UCOD_ProjMoveComponent_Base`)와 라이플 컴포넌트(`UCOD_ProjMoveComponent_Rifle`)를 점검한 내용. 플레이 테스트에서 궤적은 잘 그려지고 있으나, 코드 레벨에서 물리가 어떻게 동작하는지, 어떤 차별점이 있는지, 어떻게 더 발전시킬 수 있는지를 분석함.

---

## 내용

### 발사 순간부터 물리 흐름

```
SpawnActor(SmallCaliber)
  → BeginPlay()
      → BulletBase::BeginPlay() : OnHitDelegate 바인딩
      → ShooterWeapon에서 InitBulletData() 호출
          → Velocity = ForwardVector * 92000 cm/s  (920 m/s)
  → 매 Tick
      → ComputeAcceleration()  ← Rifle이 오버라이드
          → GravityAccel = (0, 0, -980) cm/s²
          → DragAccel = -(0.5 * ρ * Cd * A * V²) / Mass
      → Velocity += Accel * DeltaTime        ← 오일러 적분
      → Delta = Velocity * DeltaTime
      → SweepSingleByChannel (구 반지름 5cm)
          → Hit 없음 → SetWorldLocation + SyncRotation
          → Hit 있음 → OnHitDelegate → BulletBase::OnBulletHit → Destroy
```

### UE 기본 PMC vs 현재 시스템 비교

| 항목 | UE 기본 PMC | 현재 시스템 |
|------|------------|------------|
| 항력 모델 | 단순 선형 감속 (`Drag` 배율) | 실제 공기역학 공식 `F = 0.5ρCdAV²` |
| 중력 | `ProjectileGravityScale` 배율 | 독립 `GravityScale` + 물리 공식과 분리 |
| 탄종 확장 | 불가 (단일 컴포넌트) | `ComputeAcceleration()` 오버라이드로 탄종별 확장 |
| 물리 적분 | 내부 처리 (노출 안 됨) | 명시적 오일러 적분 (커스터마이즈 가능) |
| 단위계 | cm (UE 내부) | g/cm 자체 단위계로 일관 |

### 현재 코드의 문제점

**① 오일러 적분 오차 (가장 큰 문제)**
- 1차 오일러: `Velocity += Accel * dt`, `Delta = Velocity * dt`
- 92000 cm/s 속도에서 1프레임(0.016s) = **1472cm(14.7m)** 이동
- 이 구간 전체를 발사 직후 속도로 계산 → 항력 계산 오차 누적

**② Sweep 충돌 누락 가능성**
- 구 반지름 5cm로 Sweep
- 1프레임 1472cm 이동 중 얇은 오브젝트(벽, 유리)는 뚫고 지나갈 수 있음

**③ 공기밀도 고정값**
- `AirDensity = 0.001225f` (해수면 고정)
- 고도에 따른 공기밀도 변화 없음

**④ TrajectoryPoints 미사용**
- `TArray<FVector> TrajectoryPoints` — 쌓기만 하고 활용 안 함

**⑤ 스핀 안정화(Spin Stabilization) 없음**
- 현재 `SyncRotation`은 속도 방향에 즉시 맞춤
- 실제 총알은 강선에 의한 자이로 효과로 방향 변화에 저항

### 개선 방향 로드맵

**단기 (로켓탄 작업 전 고려)**
- **RK4 적분으로 교체** — 오일러 → Runge-Kutta 4차, 고속 탄환 정확도 대폭 향상
  ```
  k1 = f(t, v)
  k2 = f(t + dt/2, v + k1*dt/2)
  k3 = f(t + dt/2, v + k2*dt/2)
  k4 = f(t + dt, v + k3*dt)
  v_new = v + (k1 + 2k2 + 2k3 + k4) * dt / 6
  ```
- **서브스텝(Sub-stepping)** — 1틱을 N분할하여 Sweep 정확도 향상 (라이플에 효과적)
- **베이스에 RK4 넣으면 로켓탄도 자동으로 혜택** → 선행 작업 가치 높음

**중기 (로켓탄 이후)**
- **바람 벡터** — `WindVelocity` 필드, 항력 계산 시 `Velocity - Wind` 상대속도 적용
- **고도별 공기밀도** — `AirDensity = 0.001225 * exp(-h / 8500)` (표준 대기 모델)
- **Magnus Effect** — 스핀 총알의 횡방향 편향 (저격 시뮬에 적합)

**장기**
- **관통 & 재질 저항** — Hit 시 `PhysicalMaterial` 읽어서 관통 여부 판단, 관통 후 속도 감쇠
- **탄두 변형** — 속도에 따른 피해 감쇠 커브 (`DamageFalloff`)

## 관련 키워드

- Runge-Kutta 4차 적분 (RK4)
- 오일러 적분 수치 오차
- Sub-stepping (물리 서브스텝)
- 공기역학 항력 공식 `F = 0.5 * ρ * Cd * A * V²`
- Magnus Effect (마그누스 효과)
- Spin Stabilization (자이로 안정화)
- 표준 대기 모델 (Standard Atmosphere)
- `UCOD_ProjMoveComponent_Base`, `UCOD_ProjMoveComponent_Rifle`
