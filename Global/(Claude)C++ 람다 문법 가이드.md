# C++ 람다 문법 가이드

## 1. 람다란 무엇인가

C++에서 함수를 만드는 방법은 여러 가지가 있습니다. 가장 일반적인 방법은 이름을 가진 함수를 따로 선언하는 것입니다. 그런데 코드를 작성하다 보면, 딱 한 번만 쓸 간단한 동작을 위해 함수를 하나 통째로 선언해야 하는 상황이 자주 생깁니다. 이름을 짓고, 선언하고, 정의하는 과정이 번거롭고, 코드도 여러 곳에 흩어지게 됩니다.

람다(Lambda)는 이 문제를 해결하기 위해 C++11에서 도입된 문법입니다. 이름 없이 코드 안에서 바로 함수를 정의할 수 있게 해줍니다. 별도로 선언할 필요 없이, 필요한 자리에 바로 작성합니다.

```cpp
auto add = [](int x, int y) { return x + y; };
int result = add(3, 5);  // 8
```

람다의 기본 구조는 다음과 같습니다.

```
[캡처 목록](매개변수) -> 반환타입 { 본문 }
```

각 부분의 역할은 이렇습니다.

- `[캡처 목록]` — 람다 외부에 있는 변수를 람다 안으로 가져오는 방법을 지정합니다. 이 가이드의 핵심 주제입니다.
- `(매개변수)` — 일반 함수의 매개변수와 동일합니다. 람다를 호출할 때 전달하는 값입니다.
- `-> 반환타입` — 반환 타입을 명시합니다. 컴파일러가 추론 가능한 경우 생략할 수 있습니다.
- `{ 본문 }` — 실제로 실행될 코드입니다.

## 2. 클로저: 람다의 실체

람다를 제대로 이해하려면 컴파일러가 람다를 어떻게 처리하는지 알아야 합니다.

우리가 코드에 람다를 작성하면, 컴파일러는 그 람다를 **이름 없는 클래스**로 변환합니다. 우리가 직접 클래스를 작성한 게 아니어도, 컴파일러가 내부적으로 클래스를 하나 만들어냅니다. 이 클래스를 **클로저 타입(closure type)** 이라고 부릅니다. 그리고 이 클래스로 만들어진 객체를 **클로저 객체(closure object)** 라고 부릅니다.

```cpp
auto f = [](int x) { return x * 2; };
```

컴파일러가 정확히 이렇게 변환한다고 표준이 보장하는 것은 아니지만, 개념적으로는 다음과 비슷한 형태로 이해할 수 있습니다.

```cpp
class __Lambda {
public:
    int operator()(int x) const { return x * 2; }
};

__Lambda f;
```

`auto f`에 저장되는 것은 이 클래스의 객체입니다. `f(3)`처럼 호출하면 실제로는 `operator()`가 실행됩니다.

이 사실이 중요한 이유는, 람다가 단순한 함수가 아니라 **객체**라는 점입니다. 객체이기 때문에 멤버 변수를 가질 수 있고, 외부 변수를 그 멤버 변수에 저장할 수 있습니다. 캡처가 바로 이 멤버 변수를 만드는 과정입니다.

## 3. 빈 캡처 `[]`와 문제 상황

람다를 처음 접하면 이런 코드를 작성하고 싶어질 수 있습니다.

```cpp
int score = 100;

auto printScore = []() {
    // score를 출력하고 싶다
    std::cout << score << std::endl;  // 컴파일 에러
};
```

`score`는 바로 위 줄에 선언되어 있고, 같은 함수 안에 있습니다. 당연히 쓸 수 있을 것 같습니다. 그런데 컴파일러는 에러를 냅니다.

이유는 앞서 설명한 클로저 구조에 있습니다. 람다는 컴파일러에 의해 별개의 클래스로 변환됩니다. 이 클래스는 외부 스코프와 완전히 단절된 독립적인 존재입니다. `score`는 이 클래스 바깥에 있는 변수이고, 클래스 안에서 바깥 변수를 그냥 이름으로 참조할 수는 없습니다.

`[]`는 "아무것도 캡처하지 않겠다"는 선언입니다. 캡처하지 않은 변수는 람다 본문 안에서 존재하지 않는 변수와 같습니다.

단, 전역 변수와 함수 내 `static` 변수는 예외입니다. 이 둘은 프로그램 전체에서 접근 가능한 메모리에 저장되기 때문에, 캡처 없이도 람다 본문에서 직접 사용할 수 있습니다.

이 문제를 해결하려면 외부 변수를 람다 안으로 명시적으로 가져와야 합니다. 그 방법이 캡처입니다. 다음 장부터 각 캡처 방식을 하나씩 살펴봅니다.

## 4. `[=]` 값 복사 캡처

### 동작 방식

`[=]`를 사용하면 람다 본문에서 사용하는 외부 변수들이 **값으로 복사**되어 클로저 객체 안에 저장됩니다.

컴파일러는 람다 본문을 분석해서 어떤 외부 변수가 사용됐는지 파악합니다. 그리고 그 변수들을 클로저 클래스의 **멤버 변수**로 만들고, 람다 객체가 생성될 때 그 값을 복사해 넣습니다.

```cpp
int a = 10;
int b = 20;

auto f = [=]() { return a + b; };
```

컴파일러가 정확히 이렇게 변환한다고 표준이 보장하는 것은 아니지만, 개념적으로는 다음과 비슷하게 이해할 수 있습니다.

```cpp
class __Lambda {
    int a;
    int b;
public:
    __Lambda(int a, int b) : a(a), b(b) {}
    int operator()() const { return a + b; }
};

__Lambda f(a, b);
```

개념적으로 보면 `a`와 `b`가 클로저 클래스의 멤버 변수가 된 것처럼 동작하고, 객체 생성 시점에 값이 복사됩니다. 람다 본문에서 `a`와 `b`를 쓰는 것은 이런 멤버 변수에 접근하는 것처럼 이해할 수 있습니다.

복사가 일어나는 시점은 람다를 **호출하는 순간이 아니라**, `auto f = [=]() { ... };` 이 줄이 실행되는 순간, 즉 **람다 객체가 생성되는 순간**입니다.

### 경계 케이스

**람다를 만든 뒤 원본 변수를 바꾸면 어떻게 되나요?**

복사는 이미 람다 생성 시점에 끝났기 때문에, 원본이 바뀌어도 람다 안의 값은 바뀌지 않습니다.

```cpp
int a = 10;
auto f = [=]() { return a; };

a = 999;
std::cout << f();  // 10 출력 — 복사 시점의 값이 그대로 유지됨
```

---

**람다 본문에서 선언하지 않은 변수 `c`를 쓰면 어떻게 되나요?**

`[=]`는 본문에서 **실제로 사용된** 외부 변수만 캡처합니다. 반대로 말하면 외부에 존재하지 않는 변수를 본문에서 쓰면 캡처 여부와 무관하게 컴파일 에러가 납니다.

```cpp
int a = 10;
int b = 20;
// c는 선언되지 않음

auto f = [=]() { return a + b + c; };  // 컴파일 에러: c가 존재하지 않음
```

---

**외부에 `a`, `b`, `c`가 있는데 람다 본문에서 `a`, `b`만 쓰면 `c`도 복사되나요?**

`c`는 복사되지 않습니다. 컴파일러는 본문을 분석해서 실제로 사용된 변수만 캡처합니다. 사용하지 않은 변수는 클로저 객체에 포함되지 않습니다.

```cpp
int a = 10;
int b = 20;
int c = 30;

auto f = [=]() { return a + b; };  // c는 캡처되지 않음
```

---

**포인터 변수를 `[=]`로 캡처하면 어떻게 되나요?**

포인터 변수는 메모리 주소를 담고 있는 변수입니다. `[=]`로 포인터를 캡처하면, 그 **주소값 자체가 복사**됩니다. 주소가 가리키는 실제 데이터는 복사되지 않습니다.

```cpp
int x = 10;
int* p = &x;

auto f = [=]() { return *p; };
```

클로저 객체 안에는 `p`가 담고 있던 주소값이 복사되어 들어갑니다. 람다가 `*p`를 실행하면 그 주소로 찾아가서 값을 읽습니다. 이 주소는 원본 `x`의 메모리 위치입니다. 따라서 람다 안에서 `*p`를 통해 접근하는 것은 결국 원본 `x`에 직접 접근하는 것과 같습니다.

이것이 위험한 이유는, `x`가 언제든 사라질 수 있기 때문입니다. 예를 들어 `x`가 어떤 함수의 지역 변수였고 그 함수가 이미 종료됐다면, `x`가 있던 메모리는 더 이상 유효하지 않습니다. 그 상태에서 람다가 `*p`를 통해 그 주소에 접근하면, 존재하지 않는 메모리를 읽거나 쓰는 상황이 됩니다. 이런 상황을 **댕글링 포인터(dangling pointer)** 라고 부릅니다.

`[=]`를 사용한다고 해서 모든 것이 안전하게 독립적으로 복사된다고 생각해서는 안 됩니다. 포인터의 복사는 주소의 복사일 뿐이며, 그 주소가 가리키는 데이터의 복사가 아닙니다.

### 주의점

- 복사는 람다 **생성 시점**에 일어납니다. 호출 시점이 아닙니다.
- 포인터를 캡처하면 데이터가 아닌 주소가 복사되므로 원본과 연결이 유지됩니다.
- `[=]`로 캡처된 변수는 람다 본문 안에서 기본적으로 수정할 수 없습니다. 수정이 필요하면 `mutable` 키워드가 필요합니다. (9장에서 다룹니다.)

## 5. `[&]` 참조 캡처

### 동작 방식

`[&]`를 사용하면 람다 본문에서 사용하는 외부 변수들이 **참조로** 클로저 객체 안에 저장됩니다. 복사가 아니라 원본 변수를 가리키는 참조가 저장됩니다.

```cpp
int a = 10;
int b = 20;

auto f = [&]() { a += 5; b += 5; };
```

컴파일러가 정확히 이렇게 변환한다고 표준이 보장하는 것은 아니지만, 개념적으로는 다음과 비슷하게 이해할 수 있습니다.

```cpp
class __Lambda {
    int& a;
    int& b;
public:
    __Lambda(int& a, int& b) : a(a), b(b) {}
    void operator()() const { a += 5; b += 5; }
};
```

여기서 `operator()`가 `const`임에도 `a`와 `b`를 수정할 수 있는 이유가 있습니다. `const` 멤버 함수는 멤버 변수 자체를 바꾸지 못하는 것인데, `a`와 `b`는 참조 멤버입니다. 참조 멤버가 `const`의 보호를 받는다는 것은 "참조가 다른 변수를 가리키도록 바꿀 수 없다"는 의미이지, "참조가 가리키는 원본 값을 수정할 수 없다"는 의미가 아닙니다. 원본 값을 수정하는 것은 `const`의 제약 바깥에 있습니다.

클로저 객체가 `a`와 `b`의 참조를 멤버로 갖고 있으므로, 람다 본문에서 `a`와 `b`를 수정하면 **원본 변수가 직접 수정**됩니다.

### 경계 케이스

**람다를 만든 뒤 원본 변수를 바꾸면 람다에도 반영되나요?**

참조를 저장하고 있으므로 원본이 바뀌면 람다 안에서도 바뀐 값이 보입니다.

```cpp
int a = 10;
auto f = [&]() { return a; };

a = 999;
std::cout << f();  // 999 출력
```

---

**람다가 함수 밖으로 나가면 어떻게 되나요?**

참조는 원본 변수가 살아 있는 동안에만 유효합니다. 지역 변수의 참조를 담은 람다가 그 함수 바깥으로 나가면, 원본 변수는 소멸되지만 람다는 여전히 그 메모리를 가리키고 있습니다. 이 상태에서 람다를 호출하면 소멸된 메모리에 접근하게 됩니다. 이것을 **댕글링 참조(dangling reference)** 라고 부릅니다.

```cpp
std::function<int()> makeLambda() {
    int a = 10;
    return [&]() { return a; };  // 위험: a는 이 함수가 끝나면 소멸됨
}

auto f = makeLambda();
f();  // 미정의 동작 — a는 이미 소멸됨
```

---

**`[&]`로 캡처한 변수를 람다 안에서 수정할 수 있나요?**

참조 캡처는 `[=]`와 달리 `mutable` 없이도 원본을 수정할 수 있습니다. 참조 자체가 원본과 연결되어 있기 때문입니다.

```cpp
int a = 10;
auto f = [&]() { a = 99; };  // mutable 없이도 수정 가능
f();
std::cout << a;  // 99
```

### 주의점

- 람다가 참조하는 변수의 수명이 람다보다 짧으면 댕글링 참조가 발생합니다.
- 람다를 다른 스레드로 넘기거나 나중에 호출할 가능성이 있다면 `[&]`는 위험합니다.
- 짧고 즉시 실행되는 람다에서 사용하는 것이 안전합니다.

## 6. 개별 캡처 `[x]`, `[&x]`

### 동작 방식

특정 변수 하나만 지정해서 캡처할 수 있습니다. `[x]`는 `x`만 값으로 복사하고, `[&x]`는 `x`만 참조로 캡처합니다. 본문에서 다른 외부 변수를 쓰면 컴파일 에러가 납니다.

```cpp
int a = 10;
int b = 20;

auto f1 = [a]() { return a; };      // a만 값 복사. b는 접근 불가
auto f2 = [&a]() { a += 5; };      // a만 참조. b는 접근 불가
```

### 경계 케이스

**캡처하지 않은 변수를 본문에서 쓰면 어떻게 되나요?**

```cpp
int a = 10;
int b = 20;

auto f = [a]() { return a + b; };  // 컴파일 에러: b는 캡처되지 않음
```

`[=]`나 `[&]`처럼 자동으로 감지하지 않습니다. 명시적으로 지정한 변수 외에는 접근할 수 없습니다.

---

**같은 변수를 `[x, x]`처럼 두 번 적으면 어떻게 되나요?**

컴파일 에러가 납니다. 같은 변수를 캡처 목록에 중복해서 적는 것은 허용되지 않습니다.

```cpp
int a = 10;
auto f = [a, a]() { return a; };  // 컴파일 에러: 중복 캡처
```

### 주의점

- 캡처할 변수가 많아지면 하나씩 나열하기 번거롭습니다. 그럴 때는 `[=]`나 혼합 캡처를 검토합니다.
- 어떤 변수를 캡처하는지 명확히 드러나기 때문에 의도를 명시적으로 표현할 수 있습니다.

---

## 7. 혼합 캡처 `[=, &x]`, `[&, x]`

### 동작 방식

기본 캡처 방식을 정해두고 특정 변수만 다른 방식으로 캡처할 수 있습니다.

- `[=, &x]` — 기본은 값 복사, `x`만 참조로 캡처
- `[&, x]` — 기본은 참조, `x`만 값으로 복사

```cpp
int a = 10;
int b = 20;
int c = 30;

auto f = [=, &c]() {
    // a, b는 값 복사
    // c는 참조
    c += a + b;
};
```

### 경계 케이스

**`[=, a]`처럼 기본이 `=`인데 특정 변수도 값 복사로 명시하면 어떻게 되나요?**

컴파일 에러가 납니다. 기본 캡처가 `=`인 상황에서 특정 변수를 `[=, a]`처럼 또 값 복사로 지정하는 것은 중복이므로 허용되지 않습니다.

```cpp
int a = 10;
auto f = [=, a]() { return a; };   // 컴파일 에러
auto f2 = [=, &a]() { return a; }; // OK: 기본은 복사, a만 참조
```

---

**`[&, &x]`처럼 기본이 `&`인데 특정 변수도 참조로 명시하면 어떻게 되나요?**

마찬가지로 컴파일 에러가 납니다.

```cpp
int a = 10;
auto f = [&, &a]() { return a; };  // 컴파일 에러: 중복
```

### 주의점

- 예외 변수가 많아지면 가독성이 떨어집니다. 개별 캡처로 전환하는 것을 고려합니다.
- `[=, &x]`에서 `x`가 포인터라면 참조로 캡처한 포인터를 통해 원본 메모리에 접근하게 되므로 수명 문제를 주의해야 합니다.

---

## 8. `[this]` 캡처

### 동작 방식

클래스의 멤버 함수 안에서 람다를 만들 때, 그 클래스의 멤버 변수나 멤버 함수에 접근하려면 `this`를 명시적으로 캡처하거나, `[&]`나 `[=]` 같은 기본 캡처를 통해 암묵적으로 캡처해야 합니다.

```cpp
class MyClass {
    int value = 42;
public:
    void doSomething() {
        auto f = [this]() { return value; };  // this를 통해 value에 접근
        std::cout << f() << std::endl;
    }
};
```

`[this]`를 캡처하면 클로저 객체 안에 `this` 포인터가 저장됩니다. 람다 본문에서 `value`라고 쓰면 실제로는 `this->value`로 접근하는 것입니다. 중요한 점은, `[this]`는 멤버 변수의 값을 복사하는 것이 아니라 객체를 가리키는 포인터를 복사하는 것입니다. 따라서 람다가 멤버 변수에 접근하면 항상 원본 객체의 현재 상태가 반영됩니다.

### `[=]`와 `this`의 관계

C++17까지는 `[=]`를 쓰면 `this`도 암묵적으로 캡처됐습니다. C++20부터는 이 동작이 deprecated(권장하지 않음)로 지정되어, 컴파일러에 따라 경고 메시지가 발생할 수 있습니다. deprecated는 당장 에러가 나는 것이 아니라 "앞으로 표준에서 제거될 수 있으니 사용을 자제하라"는 신호입니다. `[=, this]`처럼 명시적으로 적는 것이 권장됩니다.

```cpp
// this를 명시적으로 캡처 — 원본 객체를 this 포인터로 접근
auto f1 = [this]() { return value; };

// 로컬 변수는 값 복사, 멤버 변수는 this 포인터로 접근
int local = 5;
auto f2 = [=, this]() { return local + value; };

// C++17: *this로 객체 자체를 복사 — 원본 객체가 소멸돼도 안전
auto f3 = [*this]() { return value; };

// C++17까지는 동작했지만 C++20부터 경고
auto f4 = [=]() { return value; };
```

`[*this]`는 C++17에서 도입된 방식으로, `this` 포인터가 아니라 객체 전체를 값으로 복사합니다. 따라서 원본 객체가 나중에 소멸되더라도 람다 안의 복사본은 독립적으로 살아 있으므로, **원래 `this` 객체의 수명** 때문에 생기는 댕글링 문제는 피할 수 있습니다. 다만 객체 내부에 포인터, 참조, 반복자처럼 다른 외부 대상을 가리키는 멤버가 있다면, 그 멤버들이 가리키는 대상의 수명 문제까지 자동으로 해결되는 것은 아닙니다.

### 경계 케이스

**`[this]`로 캡처한 상태에서 객체가 소멸되면 어떻게 되나요?**

`[this]`는 포인터를 복사합니다. 객체가 소멸되면 그 포인터는 유효하지 않은 메모리를 가리키게 됩니다. 이 상태에서 람다를 호출하면 댕글링 포인터 문제가 발생합니다.

```cpp
class MyClass {
public:
    int value = 42;
    std::function<int()> makeFunc() {
        return [this]() { return value; };
    }
};

MyClass* obj = new MyClass();
auto f = obj->makeFunc();
delete obj;  // obj 소멸
f();  // 위험: this가 가리키던 객체가 이미 소멸됨
```

### 주의점

- `[this]`는 포인터 캡처이므로 객체의 수명을 항상 확인해야 합니다.
- C++20 이상을 사용한다면 `[this]` 또는 `[=, this]`를 명시적으로 사용합니다.

## 9. `mutable`

### 동작 방식

`[=]`로 값 복사 캡처된 변수는 람다 본문 안에서 기본적으로 수정할 수 없습니다. 이는 람다의 `operator()`가 기본적으로 `const`로 선언되기 때문입니다. 클로저 클래스의 멤버 변수를 `const` 함수 안에서 수정하려 하면 컴파일 에러가 납니다.

```cpp
int a = 10;
auto f = [=]() { a = 99; };  // 컴파일 에러: const 함수에서 멤버 수정 불가
```

`mutable`을 붙이면 `operator()`의 `const`가 제거되어 복사된 멤버 변수를 수정할 수 있게 됩니다. `mutable`은 매개변수 목록 `()` 바로 뒤, 본문 `{` 앞에 위치합니다.

```cpp
int a = 10;
auto f = [=]() mutable { a = 99; };  // OK
f();
std::cout << a;  // 10 — 원본은 바뀌지 않음
```

클로저 객체 안의 복사본만 수정될 뿐, 외부 원본 변수 `a`는 변하지 않습니다.

### 경계 케이스

**`mutable`을 붙이면 원본도 바뀌나요?**

바뀌지 않습니다. `mutable`은 클로저 객체 내부의 복사본을 수정할 수 있게 해줄 뿐입니다. 원본을 수정하고 싶다면 `[&]` 참조 캡처를 사용해야 합니다.

---

**`[&]`에도 `mutable`이 필요한가요?**

필요하지 않습니다. 참조 캡처는 원본을 가리키는 참조를 저장하며, 참조를 통한 수정은 `const`의 영향을 받지 않습니다.

```cpp
int a = 10;
auto f = [&]() { a = 99; };  // mutable 없이 수정 가능
f();
std::cout << a;  // 99
```

### 주의점

- `mutable`은 복사 캡처와 함께 쓸 때 의미가 있습니다. 참조 캡처와는 무관합니다.
- 람다를 여러 번 호출하면 이전 호출에서 수정된 복사본의 값이 유지됩니다. 람다 객체가 살아있는 동안 상태가 유지됩니다.

```cpp
int a = 0;
auto counter = [=]() mutable { return ++a; };
counter();  // 1
counter();  // 2
counter();  // 3
std::cout << a;  // 0 — 원본은 그대로
```
